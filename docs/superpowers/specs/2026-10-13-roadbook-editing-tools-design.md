# 路书编辑与出行工具设计规格

## 目标

在现有路线、天气、预算、清单和 AI 调整能力上，增加一组可实际使用的行程编辑与出行辅助功能，让用户可以调整单日安排，并快速判断当天是否适合出发、预计花费多少、还缺哪些准备事项。

## 范围与非目标

### 本期范围

1. 每日行程编辑：调整出发时间、驾驶上限、住宿城市，并维护停留点顺序。
2. 编辑确认：提交后复用现有 revisions API，由 AI 生成新版本和变更摘要。
3. 每日出行工具：天气风险、日预算、油费/过路费估算、当日准备事项。
4. 路书概览：总预算、最长驾驶日、天气风险日、清单完成度。
5. 示例路书保持只读；真实路书编辑后可刷新并保留状态。

### 非目标

- 本期不实现自由拖拽地图编辑器。
- 本期不接入真实支付、酒店预订或导航执行。
- 本期不让前端直接篡改已核验路线几何数据；路线重新计算仍由服务端/AI 流程负责。

## 用户流程

### 编辑一天

用户在每日行程卡点击“调整这一天”，弹出编辑面板。面板展示当前出发时间、驾驶上限、住宿城市和停留点列表。用户可以调整字段、上移/下移停留点、删除停留点或添加一个文字停留点，然后点击“让 AI 重排这一天”。

提交前在面板底部显示影响提示：驾驶时长可能变化、住宿点可能变化、原方案会保留为上一版本。提交后复用 `/api/plans/:id/revisions`，生成新版本并显示变更摘要；请求期间按钮进入 loading，失败时保留用户输入。

### 查看出行工具

每日卡片在天气区下方显示一个“出发判断”条：

- 绿色：适合出发；
- 金色：建议留出缓冲；
- 红色：天气或驾驶强度存在风险。

同一区域显示当日估算花费、油费/过路费拆分和出发前事项。所有估算必须带“示意/估算”标识，不得伪装成报价或实时事实。

### 查看全程概览

侧栏增加“本次出行状态”卡片，展示：预算区间、清单完成度、最长驾驶日、需要重点关注的天气风险日。点击某个风险日可以跳转到对应日卡片。

## 数据与接口约定

### 行程编辑输入

新增类型 `DayEditDraft`：

```ts
type DayEditDraft = {
  dayIndex: number;
  departureTime: string;
  maxDriveHours: number;
  stayCity: string;
  stops: { id: string; name: string; note?: string }[];
};
```

`stops` 是编辑意图，不直接写入 `DayPlan.legs`。提交时转换为现有 revision instruction，服务端继续负责事实核验和路线生成。

### 出行工具计算

新增纯函数模块 `src/lib/tripTools.ts`，负责：

- `getDayRisk(day: DayPlan): "good" | "buffer" | "risk"`；
- `estimateDayCosts(day: DayPlan, partySize: number): { fuel: Range; toll: Range; total: Range }`；
- `getPreparationItems(day: DayPlan): string[]`。

计算只使用已有的路线里程、驾驶时长、天气、预算和风险字段。没有真实数据时返回估算状态，并在 UI 中明确标注。

### 持久化策略

编辑输入不新增独立数据库表。客户端将 draft 转成自然语言 instruction，提交现有 `/api/plans/:id/revisions`。清单继续使用现有 checklist PATCH 接口。预算和风险是派生数据，随当前 `TripPlan` 重新计算，不另行持久化。

## 视觉与交互

- 编辑面板沿用当前主题，不使用新的深色独立面板。
- 每日工具采用三个小型信息块：出发判断、费用估算、准备事项。
- 编辑停留点使用序号胶囊和上下箭头按钮，移动端按钮必须有文字或 aria-label。
- 错误、待核验和估算状态使用现有 `StatusBadge` / `showToast` 风格，文案避免只显示“待定”。
- 只读示例路书点击编辑时给出明确提示，不打开可提交的编辑状态。

## 验收标准

1. 真实路书可打开每日编辑面板，修改字段和停留点顺序。
2. 提交编辑调用现有 revisions API，成功后显示版本号和变更摘要，并刷新当前路书。
3. 示例路书不会发送修改请求。
4. 每日卡片能显示出发判断、估算费用和至少一条准备事项；缺少天气时显示可理解的“暂无预报”状态。
5. 全程概览显示预算、清单完成度、最长驾驶日和风险日，并可跳转。
6. 键盘可关闭编辑面板，表单控件有可读标签，移动端不出现横向溢出。
7. 所有估算文案带“估算/示意”说明，不被呈现为实时报价或导航事实。
